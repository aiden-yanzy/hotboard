# 上游同步（升级 DailyHot / DailyHotApi 的正确姿势）

本项目的前端与采集引擎都是**上游开源项目的克隆 + 我们的改动**。
为了让「升级上游」不炸我们的改动，所有改动都以 **patch 存档**在 `deploy/patches/`：

| 文件 | 对应 | 基线 commit | 改动处 |
|---|---|---|---|
| `web-vs-imsyy-8b91ad9.patch` | `apps/web` ← `imsyy/DailyHot`（MIT） | `8b91ad9` | 49 |
| `engine-vs-DailyHotApi-36c77e3.patch` | `apps/engine` ← `DailyHotApi` | `36c77e3` | 7 |

另有一处**故意保留的差异**（不在 patch 里，因为它是我们的构建修复）：
`apps/engine/Dockerfile` 把 pnpm 钉到 9.x（上游写 `npm install -g pnpm`，现在会装到 10+，
默认禁止依赖执行构建脚本 → esbuild 装不上，构建直接失败）。上游原版存档为
`apps/engine/Dockerfile.upstream`，升级时先 diff 再合并。

---

## 升级 web（前端）

```bash
cd /tmp && git clone --depth 50 https://github.com/imsyy/DailyHot.git web-up
cd web-up && git checkout <目标 commit>
git diff 8b91ad9 HEAD --stat          # 看看上游改了哪些文件，是否碰了我们的改动点
git format-patch 8b91ad9 --stdout > /tmp/upstream-web.patch
# 到我们仓库里试合
cd ~/Projects/hotboard/apps/web
git apply --3way --check /tmp/upstream-web.patch    # 只检查
git apply --3way /tmp/upstream-web.patch            # 真合
npm run build && 验证 :6600
# 合完更新 patch 存档（这是新的「我们 vs 上游」差异）
```

> `apps/web` 里我们的核心改动：分类顶栏（`CategoryBar`）、热点推荐（`List.vue` + `/rising`）、
> 右侧栏（广告/友链/备案）、品牌与图标、`VITE_GLOBAL_API` 改相对路径、`vite.config.js` 的 PWA manifest。

## 升级 engine（采集引擎）

```bash
cd /tmp && git clone --depth 50 https://github.com/imsyy/DailyHotApi.git eng-up   # 或对应上游仓库
cd eng-up && git checkout <目标 commit>
git diff 36c77e3 HEAD --stat
cd ~/Projects/hotboard/apps/engine
git apply --3way <上游 diff>
diff Dockerfile.upstream Dockerfile      # 确认 pnpm 钉版本那一行还在
# 重新构建
cd ~/Projects/hotboard && docker compose build engine && docker compose up -d engine
curl -s -m 25 http://127.0.0.1:6688/zhihu | head -c 200
```

> `apps/engine` 里我们的核心改动：RSS 路由 `pickCover()` 抽封面、`nytimes/ifanr/52pojie/nodeseek` 等路由的字段补齐。

## 重新生成 patch 存档

```bash
cd ~/Projects/hotboard
# web
diff -ruN <上游干净副本>/src apps/web/src > deploy/patches/web-vs-<上游sha>.patch
# engine（举 RSS 路由）
diff -ruN <上游干净副本>/src/routes apps/engine/src/routes > deploy/patches/engine-vs-<上游sha>.patch
```

## 底线

* 升级前 `git status` 必须干净（我们的改动已提交）→ 出问题 `git checkout .` 一键回退。
* 升级只做「拿上游」这一件事，**不顺手重构**；构建完必须实测：`:6600` 首页 + `:6700/api/health` + `:6688/<源>`。
* 上游许可：DailyHot / DailyHotApi 为 **MIT** → 可商用，但**必须保留版权与许可声明**
  （页脚/右侧栏的 DailyHot 出处链接是我们的合规保留，不要删）。
