> 目标（用户 2026-10-19）：**后续还要持续加源，所以这次要把抓取逻辑规范起来**，合并 dailyhot/newsnow 只是它的第一个应用。
> 状态：**设计待批准**，尚未动代码。

## 一、现状评估（实测）

### 1.1 已经对的部分 ✅
`jobs/collector/collect.py`（395 行）本身就是可插拔设计：

| 函数 | 职责 | 评价 |
|---|---|---|
| `load_config()` | 读 `config.yml` + 环境变量覆盖 `engines.<name>.base_url/path/timeout` | ✅ 引擎注册表已存在 |
| `normalize(engine, src_id, payload)` | **唯一的"形状分发"点**（dailyhot `data` / newsnow `items` / 通用 `data` 兜底） | ⚠️ 引擎耦合在这里 |
| `fetch()` / `reachable()` | HTTP + 引擎可达性预检（不可达整批跳过，不拖累其他引擎） | ✅ |
| `crawl()` | 遍历 `sources where enabled` → 抓 → 归一化 → upsert `items` → insert `snapshots(rank, heat)` → 回写 `last_ok_at/last_err/items_seen` → 记 `crawl_runs` | ✅ 链路完整 |
| `main()` | `--init-schema / --bootstrap / --engine / --dry-run / --loop / --interval` | ✅ |

### 1.2 缺的部分 ❌
1. **没有统一契约**：`Item` 结构散在 `normalize` 里，新引擎必须改 `collect.py`
2. **没有"自研源"入口**：所有源都必须经由一个 HTTP 上游（dailyhot / newsnow），无法直接实现抓取
3. **形状分发写死在函数里**：`if engine == "dailyhot" ... elif "items" in payload` → 加第三个引擎/自研源就要改核心
4. **没有适配器级测试**：只有 `verify_pluggable.sh` 的引擎级验证

### 1.3 数据模型（不变）
- `sources(id, engine, src_id, name, category, enabled, last_ok_at, last_err, items_seen)`
- `items(source_id, ext_id, title, url, url_hash, title_sim, first_seen, last_seen, meta)`；去重键 `(source_id, url_hash)`
- **`snapshots(item_id, ts, rank, heat)`** ← `rank + heat` 时序 = 本项目护城河
- 实测字段能力：**dailyhot 提供 `hot`（热度）**；**newsnow 不提供**（`extra` 只有 hover/info/date/icon）

## 二、设计：适配器契约（核心产出）

### 2.1 目录结构
```
jobs/collector/
├── collect.py                 # 只做：调度 / 入库 / 统计（几乎不动）
├── config.yml                 # engines 注册表 + adapters 开关
├── adapters/                  # ★ 新增
│   ├── __init__.py            # 注册表（自动发现 + 显式注册）
│   ├── base.py                # ★ 契约：Item / Adapter / HttpJsonAdapter
│   ├── engines.py             # 把现有 dailyhot / newsnow 包成 adapter（兼容旧路径）
│   ├── xueqiu.py              # 自研源：一个源一个文件
│   ├── cls.py
│   └── ...
└── tests/
    └── fixtures/              # 每个源的离线响应样本（源改版时先跑测试）
```

### 2.2 契约
```python
# adapters/base.py
@dataclass
class Item:
    ext_id: str                 # 源内稳定唯一 id（跨轮次不变）
    title: str
    url: str | None = None
    rank: int | None = None     # 榜单顺序（一般 = 返回顺序）
    heat: int | None = None     # 热度；拿不到必须是 None
    desc: str | None = None
    cover: str | None = None
    author: str | None = None
    timestamp: int | None = None
    extra: dict | None = None   # 兜底原样保留

class Adapter(Protocol):
    src_id: str                 # 对应 sources.src_id
    name: str                   # 中文名
    category: str               # 综合/科技/娱乐/开发/社区/购物
    def fetch(self, client: HttpClient) -> list[Item]: ...
```
- `HttpJsonAdapter`：给"纯 JSON API"的源用的基类（只写 `url` + `parse(payload)`）
- `engines.py`：把 dailyhot/newsnow 包成 adapter —— **现有两个上游的行为完全不变**，只是统一入口

### 2.3 十条规范（写进 `adapters/README.md`）
1. **一个源 = 一个文件**（`adapters/<src_id>.py`），顶层暴露 `SRC_ID / NAME / CATEGORY / fetch()`
2. **`fetch()` 只负责"取 + 解析"，返回 `list[Item]`**；**禁止在适配器里碰数据库**（入库统一由 `collect.py` 做 → 保证可测、可 dry-run）
3. **`rank` = 返回顺序**（第 1 条即 rank 1）；适配器不要自行打乱榜单
4. ⭐ **`heat` 拿不到就 `None`**：**严禁填 0 或假值** —— 否则污染 `snapshots.heat`，涨跌/热度趋势失真
5. **`ext_id` 必须稳定**：同一条目跨轮次必须同 id，否则 `first_seen/last_seen` 与去重全部失效
6. **HTTP 一律用注入的 client**：超时/重试/限速/UA 统一在一处；禁止各适配器自建连接
7. **解析失败抛明确异常**（带源名与原因）→ 由 `collect.py` 记入 `sources.last_err`，巡检可见
8. **每个适配器配离线 fixture 测试**：用 `tests/fixtures/<src_id>.json` 跑解析，不依赖网络
9. **新增源三步**：① 写 `adapters/<src_id>.py` ② `--dry-run` 验证（打印条数与样例）③ 注册进 `sources`（bootstrap 或 SQL）
10. **兼容层永不删**：旧引擎路径（`base_url` + `path`）保留，直到对等迁移完成；`base_url` 置空即停用
